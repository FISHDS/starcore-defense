# 星核防線頭目骨架與動作製作範本
建立日期：2026-10-16

這份範本讓新頭目沿用同一套長鏈骨架、受擊反應和狀態切換。新造型只需要提供輪廓、顏色、部件比例、動作幅度和專屬攻擊；不應為了換外觀重寫長鏈行走或碰撞規則。

## 一、骨架如何組成

- **頭節**：`segments[0]` 是頭部，決定整條長鏈前進方向。頭節不接受傷害；身體被擊破時，頭節沿原路回退一格。
- **身體節**：`segments[1…n]` 沿頭節走過的路線排列；節點被擊破後，其後方節點會補齊間距，避免尾巴被扯斷或瞬移。
- **關節**：每對相鄰身體節的中點。`resolveBossPose` 依時間與造型擺幅加上小幅搖動，圖像部件沿相鄰節方向旋轉。
- **獨立部件**：刀、盾、角、嘴、喇叭或光圈以頭節為錨點繪製；裝備型頭目可以讀取 `resolveBossEquipmentPose` 的手勢與揮擊角度。
- **核心弱點**：畫面上的亮點、甲殼或護盾必須對應真正的遊戲節點規則；若只是裝飾，就不能暗示玩家那是可破壞弱點。

## 二、共用動作狀態

狀態由 `resolveBossPose` 依 rig 計時欄位選擇，優先順序為死亡、受擊、攻擊、預警、待機，最後才是移動。

| 狀態 | 進入時機 | 可用的姿勢變化 | 手機畫面應讀出的訊息 |
|---|---|---|---|
| `idle` | 頭目尚未開始攻擊 | 輕微呼吸、漂浮或零件轉動 | 正在盤繞行進 |
| `move` | 沒有其他狀態時 | 身體節有方向性的波浪，頭部跟著路徑轉向 | 長鏈正在靠近守點 |
| `telegraph` | `rig.telegraphFor > 0` | 顯著蓄力；可用亮光、張嘴、舉刀、轉向或拉長身體 | 預警有方向且可看懂攻擊目標 |
| `strike` | `rig.strikeFor > 0` | 武器揮出、嘴部張開、傘面脈衝或部件彈出 | 攻擊正在發生，可轉向射擊攔截 |
| `hurt` | 頭目身體節受到直接命中 | 白閃、短暫壓縮、向後震動 | 命中確實落在頭目身上 |
| `dying` | `chain.dead` 或死亡計時中 | 身體鬆脫、下沉、淡出或爆裂 | 頭目已被擊倒；死亡特效有完整播放時間 |

`rig.phase` 在剩餘身體節低於原始數量一半時切換到第二階段。第二階段至少要改變一個玩家能觀察到的行為，例如攻擊間隔、出手數量、護盾輪替或弱點開窗；只把顏色變紅不算階段變化。

## 三、外型資料填寫表

新增 profile 前先複製以下欄位，並以 80–90px 頭部、40–50px 身體節驗收：

```js
{
  id: 'meme-example',
  name: '新頭目名稱',
  silhouette: 'core', // mantis、coral、jelly、ram、core
  colors: {
    shell: '#7b89a1',
    shadow: '#283247',
    glow: '#82f1ed',
    eye: '#fff4d8',
  },
  anatomy: {
    headScale: 1.05,  // 0 < 數值 <= 60；建議 0.85–1.25
    bodyScale: 1.0,   // 0 < 數值 <= 60；建議 0.8–1.2
    hornLength: 12,   // 0 < 數值 <= 60
    jawWidth: 18,     // 0 < 數值 <= 60
    finLength: 15,    // 0 < 數值 <= 60
  },
  motion: {
    sway: 2.4,        // 0–30；建議 1–6，避免小螢幕抖動
    pulse: 0.06,      // 0–30；建議 0.02–0.12
    attackReach: 14,  // 0–30；攻擊姿勢伸展距離
    hurtKick: 8,      // 0–30；受擊回彈幅度
  },
}
```

顏色必須是六位 `#RRGGBB` 色碼。頭、身體和裝備優先使用透明 PNG 或 SVG；手機版素材要先縮到接近實際繪製大小再進入每幀繪圖，不能讓數千像素原圖反覆參與 Canvas 繪製。輪廓要靠外形而非只靠換色區分。

## 四、換造型時必須回答的設計問題

1. 玩家縮小看一眼，靠哪三個特徵認出它？頭節和身節各自長什麼樣？
2. 這隻頭目沿哪條路線逼近？是單向螺旋、繞核心、交錯分岔、折返，還是兩頭互相掩護？行走路線最終必須到達關卡守點。
3. 招牌攻擊的**預備姿勢、危險方向、可反制方式、出手姿勢、半血後變化**各是什麼？玩家只可原地轉向，不可要求走位或閃避。
4. 攻擊預警中，玩家可以瞄準哪一段攻擊彈道來攔截，或可以集中打哪個真正有效的身體部位？
5. 額外掉落若會出現在畫面，必須明確分辨攻擊和獎勵。本作沒有回血掉落，也不要求玩家移動接觸拾取。

## 五、接入與驗收步驟

1. 將造型資料加入 `boss-profiles-a.js` 或 `boss-profiles-b.js`；新增專屬行為時放在明確的 profile ID 分支或獨立模組，不要把所有頭目塞進同一個通用攻擊。
2. 若使用點陣圖，將每個畫面部件及其用途列在 profile 的 `parts` 欄位，並在 `boss-art.js` 加載一次、縮小一次，再於每幀重用縮圖。
3. 在 `tests/boss-rig.test.js` 測資料有效、骨架節數/關節數相符、六種狀態各有姿勢、第二階段狀態切換。若有專屬攻擊，再新增同名 profile 的行為測試。
4. 先放入快速體驗入口，逐一確認 360×740 與 390×844 畫面。頭部、身體節、預警方向和寶箱都需能辨認；狀態切換不能讓畫面卡頓，也不能因高解析原圖造成掉格。
5. 只有主代理完成手機尺寸實測並通過測試後，才把新頭目安排進正式關卡。任何一項看不清、不能靠固定位置轉向反制或攻擊路線與既有頭目相同，都退回重做。

## 六、現有測試命令

```sh
node --test tests/boss-rig.test.js tests/boss-patterns.test.js tests/knife-shield-combat.test.js tests/screech-cat.test.js
```

`tests/boss-rig.test.js` 目前涵蓋 profile 欄位、長鏈關節、受擊姿勢、第二階段、預警鎖定和固定核心位置；專屬頭目需再補其招牌動作和攻擊彈道測試。
